Firmenbriefing in Copilot Studio – Einfacher Start

Ein Orchestrator, fünf Rollen-Agenten, drei Werkzeuge, ein SharePoint-Ordner je Lauf. Ohne Basis- und Schlussreview, ohne Trigger-Kette, Cache und Modul-Orchestrator. Alles davon ist später ergänzbar. Stand 13.11.2026.
1 · EinstiegChat in Teams oder M365 Copilot
Nutzer
Schreibt: „Briefing zu [Firma], Fokus: [Thema], Gesprächspartner: [Person]“.
Erhält am Ende den Link auf die fertige HTML (Rückpfeil).

Für die Modulvariante genügt: „Nur Portfolio zu [Firma]“.
Orchestrator-Agent „Firmenbriefing“
Instructions: Auftragswahl, Zuständigkeit, Quellenregeln (Kern aus CLAUDE.md). Antwortet als einziger dem Nutzer.
  • Schritt 1 run_id vergeben, Ordner anlegen, auftrag.json schreiben
  • Schritt 2 Faktenrollen nacheinander aufrufen; bei „nur Portfolio“ nur diese eine
  • Schritt 3 Interpretation aufrufen (entfällt bei Modulauftrag)
  • Schritt 4 HTML rendern lassen, Link zurückgeben
Modell: im Mandanten eingestellter Standard. Konversationsverlauf wird nicht an die Rollen weitergegeben.

3 · Werkzeugeje Agent nur das Nötige
Websuche
eingebaut, Bing-Grounding; nur für die Faktenrollen aktiv.
⚠ Liefert Treffer, nicht sicher den Volltext oder PDFs. Erste Hostprobe.
Agent Flow „Datei schreiben / lesen“
zwei Flows mit SharePoint-Aktionen. Eingabe: run_id, Dateiname, Inhalt. Jede Rolle schreibt genau ihre Datei.
Prompt-Tool „HTML rendern“
HTML-Vorlage als Wissen + JSON-Dateien → briefing.html
⚠ LLM-gefüllte Vorlage, kein Python-Renderer.
