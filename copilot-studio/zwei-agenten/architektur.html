Firmenbriefing in Copilot: zwei Agenten, Skills als ZIP-Pakete

Agent Builder in Microsoft 365 Copilot oder Copilot Studio. Agent 1 erstellt ohne Prüfung. Agent 2 prüft nur auf Wunsch, in eigenem Kontext. Version 3, 24.11.2026. Paket gebaut, im Mandanten noch nicht getestet.
Nutzer
1. „Briefing zu [Firma], Fokus: [Thema], Gesprächspartner: [Name], [Position]“ · bei Abbruch wegen Länge: „weiter“
2. optional: „prüfen“, „nur Portfolio prüfen“ oder „nur A-Fakten prüfen“ · Copilot Studio: im selben Chat · Agent Builder: im Agenten „Briefing-Prüfung“ mit Datei
Agent 1 „Firmenbriefing“ – erstellt
Instructions: Auftrag erkennen, Defaults, Reihenfolge, Arbeit in Phasen mit Zwischenstand in der Datei, Hinweis „ungeprüft“.

Instructions: nur prüfen, keine neuen Fakten, Korrekturen nur vorschlagen. A-Fakten vollständig, B-Fakten Stichprobe.

Ergebnis berechnet das Skript; A-Claim abweichend oder nicht belegt = nicht bestanden
Paket: zehn Skills als ZIP mit SKILL.md im Hauptordner, Instructions je Agent, Machbarkeitstest; gebaut und geprüft mit tools/build.py. Agent Builder: Skill-Skripte laufen dokumentiert, Prüfung per Agentwechsel. Copilot Studio: zusätzlich Übergabe im Chat und geteilte Skills.
⚠ Offen: Ob ein Agent eine bestimmte URL oder ein PDF öffnen kann, ist nicht dokumentiert; deshalb trennen die Urteile „im Original bestätigt“ und „durch Suche gestützt“. Ob HTML-Dateien hochgeladen und gelesen werden, ist nicht dokumentiert; deshalb gibt es die Excel-Übergabe. Beides klärt der Machbarkeitstest von etwa 30 Minuten.
