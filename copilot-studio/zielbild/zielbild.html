Firmenbriefing in Copilot Studio

Vereinfachte Version B des bestehenden Briefing-Tools: fünf Agenten statt vierzehn Rollen, ein Agent Flow als Taktgeber, ein Dossier je Lauf. Zwei Abläufe: Vollbriefing und Kurzbriefing.

Welcher Copilot-Studio-Baustein wofür

Microsoft empfiehlt, mit einem Agenten zu beginnen und nur dort zu trennen, wo eigene Werkzeuge, eigenes Wissen oder eigene Regeln nötig sind. Für dieses Tool heißt das: ein deterministischer Flow als Rückgrat, wenige eigenständige Agenten, Code nur für Abruf, Formatprüfung und Rendering.

„Workflows“ ist in Copilot Studio der Bereich, in dem Agent Flows angelegt werden. Gemeint ist hier also ein Agent Flow.

Viele JSON-Dateien oder ein Dossier?

Variante 1

Eine Datei je Rolle (wie heute)

  • Jede Rolle schreibt nur ihre Datei, keine Schreibkonflikte bei Parallelarbeit
  • Gezielte Nachprüfung nur geänderter Module, Wiederaufnahme nach Abbruch
  • Kleine Eingaben je Agent, weniger Verbrauch
  • Viele Lese- und Schreibaktionen und Pfade im Flow, mehr Fehlerquellen
  • Quellen-IDs müssen über Dateien hinweg abgeglichen werden
  • Für Fachanwender schwer zu überblicken
Variante 2

Ein gemeinsames Dossier, Agenten schreiben selbst

  • Ein Ort für alles, leicht zu öffnen und zu archivieren
  • Einfacher Flow
  • Parallel schreibende Agenten überschreiben sich gegenseitig
  • Jeder Agent bekommt schnell das ganze Dossier, teurer und unschärfer
  • Ein Formatfehler gefährdet den ganzen Lauf
Empfehlung

Ein Dossier, nur der Flow schreibt

  • Agenten geben ihren Abschnitt strukturiert zurück, der Flow trägt ihn ein. Keine Konflikte.
  • Abschnitt je Agent erhält die Zuständigkeit und erlaubt gezielte Korrekturen
  • Der Flow übergibt jedem Agenten nur die Abschnitte, die er braucht
  • Ein gemeinsames Quellenregister im Dossier, keine doppelten Quellenangaben
  • Abschnitte brauchen ein festes Format, das der Flow prüft

Quellen müssen als Feld im Abschnitt stehen (URL, Datum, Belegstelle). Microsoft weist darauf hin, dass Zitate bei der Rückgabe zwischen Agenten verloren gehen können. Wenn das Tool später für viele Läufe genutzt wird, können Fakten und Quellen von der Datei in Dataverse-Tabellen wandern. Dann sind Prüfstatus je Aussage und Wiederverwendung zwischen Läufen möglich.

Welche Claude-Modelle im eigenen Mandanten produktiv freigegeben sind, legt die Administration fest. Microsoft beschreibt Anthropic-Modelle teils noch als Auswahl für nicht produktive Agenten. Eine Effort-Einstellung je Agent ist in Copilot Studio nicht dokumentiert.

  2. Stufe 1 · Durchstich KurzbriefingFront-Agent, Auftragsliste, Agent Flow mit Zweig „Kurz“, Recherche-Agent, Prüf-Agent, Kurzfassung als Word-Datei.Fertig, wenn ein echter Lauf durchläuft, jede Aussage eine URL trägt und ein absichtlich falscher Fakt zurück an die Recherche geht und danach korrigiert besteht.
  3. Stufe 2 · Quellen richtig lesenTool „Quelle abrufen“ als Custom Connector auf Basis des vorhandenen Quellen-Caches: HTML und PDF, Seitenangabe, Abrufdatum.Fertig, wenn ein Geschäftsbericht mit Seitenangabe belegt wird.
  4. Stufe 3 · Vollbriefing FaktenRecherche-Tiefe-Agent, Zweig „Voll“ mit vier Modulen, Schleife je Fokusthema, Prüfung je Modul, Rücklauf an das Modul bis zum Bestehen.Fertig, wenn zwei Fokusthemen getrennte Abschnitte liefern, eine Korrektur nur das betroffene Modul neu startet.
  5. Stufe 4 · BewertungBewertungs-Agent für Positionierung und SWOT, Schlussprüfung.Fertig, wenn jede Bewertung auf geprüfte Fakten verweist.
  6. Stufe 5 · AusgabeTool „Briefing rendern“ mit der bestehenden HTML-Vorlage, zusätzlich PDF, Ablage in SharePoint.Fertig, wenn das Ergebnis der heutigen HTML entspricht und in SharePoint geöffnet werden kann.
  7. Stufe 6 · Freigabe für alleAls Lösung von Test nach Produktion übertragen, Veröffentlichung in Teams, Verbrauch beobachten, Kurzanleitung.Fertig nach einem Pilot mit drei Nutzern und drei Firmen.

Vor Stufe 1 im Test klären

  • Wartet die Flow-Aktion „Agent aufrufen“ auf das Ergebnis, auch wenn eine Recherche mehrere Minuten dauert?
  • Laufen Agentenaufrufe im Flow parallel oder nur nacheinander? Nacheinander funktioniert, dauert aber länger.
  • Welche Claude-Modelle sind im Mandanten produktiv nutzbar?
  • Wie lang dürfen Anweisungen je Agent sein? Das bestimmt den Zuschnitt der Auftragskarten.
  • Was kostet ein Lauf in Copilot Credits? Abgerechnet werden Modell-Tokens, Werkzeuge und Flow-Aktionen. Jeder Rücklauf kostet erneut.
  • Schleifen im Agent Flow haben eine technische Höchstzahl an Durchläufen (im Express-Modus 100). Was passiert, wenn sie erreicht wird?

Auftrag an Claude für die nächste Ausarbeitung

Diesen Text zusammen mit dem Repository (CLAUDE.md, references/, scripts/) an Claude geben, um Version B weiter auszuarbeiten: Auftragskarten, Dossier-Format und Flow-Schritte.

Du kennst das Firmenbriefing-Tool aus den beigefügten Dateien (CLAUDE.md, references/, scripts/).
Ziel: Version B für Microsoft Copilot Studio, einfach und modular, Schritt für Schritt umsetzbar.

Rahmen:
- 5 Connected Agents: Front-Agent, Recherche (Sonnet 5.5), Recherche Tiefe (Opus 5.5), Prüfung (Sonnet 5.5, ohne Chatverlauf), Bewertung (Opus 5.5).
- Ein Agent Flow „Briefing-Lauf“ steuert Reihenfolge, Schleife je Fokusthema und Prüftore.
- Bei „nicht bestanden“ geht der Abschnitt wieder hoch an das zuständige Modul, bis die Prüfung bestanden ist.
- Ein Dossier je Lauf in SharePoint; Agenten liefern Abschnitte zurück, nur der Flow schreibt.
- Tools per Custom Connector: „Quelle abrufen“ (source-cache.py) und „Briefing rendern“ (render-briefing.py).
- Zwei Zweige: Kurzbriefing und Vollbriefing.

Liefere:
1. Je Modul eine Auftragskarte (max. 1 Seite) aus den bestehenden Regeln, ohne fachliche Abstriche bei Quellenprüfung.
2. Das Dossier-Format (JSON-Schema) mit Quellenregister und einem Abschnitt je Agent.
3. Die Flow-Schritte für Stufe 1 (Kurzbriefing) als nummerierte Liste mit Copilot-Studio-Aktionen.
4. Eine Liste der heutigen Regeln, die in Version B entfallen oder in Code wandern, jeweils mit Begründung.
